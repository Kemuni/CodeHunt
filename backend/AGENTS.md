# Работа с backend

Перед изменениями прочитай [CONTEXT.md](CONTEXT.md) и [текущий план](docs/task-domain-implementation-plan.md), затем сверь их с кодом и `git status`. Контекст — снимок, новые инструкции пользователя имеют приоритет. Файлы приложения и рабочая БД могут измениться после даты аудита.

## Соглашения проекта

- Комментарии и Swagger summary на русском. Не дублируй summary описанием функции и не используй в нём точку с запятой.
- Успешные ответы через SuccessResponse, общие схемы в app/schemas/common.py. Health-check сохраняет свой контракт.
- Ожидаемые ошибки — именованные наследники DomainError с сообщением по умолчанию и возможностью переопределения. Не передавай HTTP-коды и строковые коды ошибок в каждом raise.
- PATCH-схемы явные. Различай отсутствие поля и null. Не возвращай динамический partial и удалённую проверку верхней границы BIGINT в API/сервисах.
- Даты с часовым поясом. Для запросов и ограничений предпочитай SQLAlchemy, не возвращай ddl.py с SQL-триггерами.
- Task остаётся строгим. Незавершённые данные — TaskDraft. Сохраняй правила уровня групп, снимков решений, владельца файлов и revision.
- Тесты с БД/MinIO выполняй в Docker через Testcontainers. Для схемы используй Base.metadata.create_all/drop_all. Не подменяй PostgreSQL SQLite и не используй рабочую БД.
- Не применяй рабочие миграции, seed или очистку файлов только ради теста. Не меняй .env и не выводи его содержимое.
- Сохраняй незакоммиченные изменения пользователя. Обновляй документацию при изменении API и правил. Записывай фактический результат проверок и оставшиеся ошибки.
