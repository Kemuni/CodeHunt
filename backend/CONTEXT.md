## Что сохранять

- Новая задача создаётся через `TaskDraft → publish`. Черновик хранит неполную форму, принадлежит администратору и использует `revision` для формы, файлов, удаления и публикации. Только код `draft_revision_conflict` переводит frontend в состояние конфликта; другие 409 допускают исправление и повтор.
- У `Task` нет `status`: видимость задаёт `is_hidden`. Публичные маршруты скрывают такие задачи даже от администратора; редактор доступен админам. Платные задачи (`is_paid`) и их файлы/пресеты сейчас доступны только админам. Снимки решений не должны обходить это правило.
- Отдельные GET `/tasks/by-slug/{slug}/presets` и `/editor/tasks/{id}/presets`, поле `parent_task_id`, API решений и их вычисляемый статус сохранены по указанию пользователя.
- `PUT /editor/tasks/{id}` атомарно записывает поля, пресеты и дерево, сохраняя ID. У готовой задачи нет защиты от устаревшего PUT через revision. Удаление не требует предварительного скрытия; внешние ссылки по-прежнему защищены.
- В TaskDetail пресеты — объект `easy/medium/high`, каждый содержит собственные пункты уровня. При создании решения внутренняя конфигурация накопительная. Снимки не меняются после правки источника.
- Группы и потомки имеют один level, не более трёх уровней групп и 1000 узлов. Пункт внутри третьей группы допустим. Нумерация пунктов вычисляется при чтении; в таблицах состава хранится только `position`.
- Фото — максимум 5 МиБ, 20 млн пикселей и четыре фото в галерее; хотя бы одно обязательно при сохранении/публикации задачи. Черновик допускает пустую галерею. Вложения — до 50 МиБ. Старое окружение с MAX_PHOTO_BYTES=10 МиБ ограничивается новым максимумом без редактирования `.env`.
- Next.js ограничивает запросы по маршрутам: JSON 2 МиБ, пакет фото 21 МиБ, вложение 51 МиБ с запасом multipart и таймаут 120 секунд. Backend проверяет только единый верхний предел тела 64 МиБ без таблицы маршрутов и собственного таймаута. Проверки отдельных файлов сохранены; Cache-Control задаёт отдельный ResponseCacheMiddleware. Большие файлы из MinIO выдаются блоками 64 КиБ; Redis хранит только файлы до MEDIA_CACHE_MAX_BYTES (по умолчанию 1 МиБ).
- Проверка доступа к медиа выполняется перед кешем, HEAD и 304. URL постоянные, браузерные ответы `private, no-cache`; JSON зависит от прав и отдаётся `no-store`. Удаление файлов использует транзакционную очередь БД; компенсация прерванной загрузки ещё не гарантирует отсутствие сирот.
- GitHub identity обязательна; роль пересчитывается по подтверждённым email и ADMIN_EMAILS. Next.js читает backend-токен из зашифрованной cookie, не доверяет клиентскому Authorization и не выдаёт токен JavaScript.
- `/tasks/[slug]` получает TaskDetail на сервере, формирует metadata и настоящий 404, передаёт данные в клиентский компонент. Общего кеша персональных ТЗ нет. Остальные изображения после первого получают `loading=lazy`. Кеш публичных деталей инвалидируется по префиксу ключей со slug, включая старый адрес.
