# CodeHunt backend

Backend конструктора пет-проектов для начинающих разработчиков. Администратор собирает задание из переиспользуемых шаблонов, конкретных требований, групп, пресетов и файлов. Пользователь выбирает уровень, исключает любые пункты и ведёт независимый чек-лист своего решения.

Документация обновлена **9 ноября 2026 года** после упрощения API и синхронизации frontend/backend. Чтение пресетов возвращает пункты только своего уровня; создание решений сохраняет внутренний накопительный расчёт `composition.configuration`. Номера пунктов вычисляются при чтении внутри каждого уровня; фото и вложения выдаются через медиапрокси с Redis-кэшем.

## Быстрый запуск

Стек: Python 3.12+, FastAPI, Pydantic, SQLAlchemy asyncio, PostgreSQL 18, Alembic, MinIO, uv. Точные зависимости фиксируются в `uv.lock`.

Из корня репозитория, после создания `.env` по `.env.example`:

```sh
make sync-all
make up-dev-env
make migrate
make seed
make fastapi-dev
```

`make seed` — необязательное явное создание демонстрационных пользователей и заданий. Повторный запуск не дублирует записи. ID выводятся скриптом, фиксированные ID из тестов нельзя переносить в рабочее окружение.

Swagger: `http://127.0.0.1:8000/docs`. OpenAPI: `/openapi.json`. API имеет префикс `/api`. Для запуска всего приложения в Docker: `make up-all`. Рабочие миграции применяются Alembic, актуальная вершина — `fc806193b753`.

Вход через GitHub OAuth создаёт пользователя и сессию на 24 часа. Backend проверяет принадлежность OAuth-токена нашему приложению и подтверждённые email. Администраторы задаются через `ADMIN_EMAILS`; пустой список никому не даёт прав. `X-User-ID` больше не принимается. Черновики доступны только владельцу, решения — автору. Настройка: [development.md](docs/development.md#github-oauth).

## Контракты, которые важно не перепутать

- Публичные детали задачи — только GET `/tasks/by-slug/{slug}`; GET `/tasks/{id}` удалён. Редактор и создание решений продолжают использовать ID; публичные пресеты читаются по slug.
- Библиотека `/task-complications/library`: массив `{developer_type, categories}`. Общий шаблон `TaskComplication` больше не имеет `slug`, у Task slug сохранён.
- В TaskComplicationLink и TaskComplicationLinkGroup хранится только `position` — порядок соседей. API вычисляет `order_number` пунктов с 1 внутри каждого уровня при обходе дерева сверху вниз. У групп номера нет.
- Группа требований имеет обязательный `level`. Её дочерние группы и пункты имеют тот же уровень. Вложенность допускается до 10 уровней, всего до 1000 элементов.
- Создание задания — только через черновик и publish. PUT `/editor/tasks/{id}` атомарно сохраняет поля, `items` и массив `presets`. Детали возвращают объект `presets.easy/medium/high`, каждый блок содержит `{preset, complications}` только своего уровня. Верхнеуровневого `complications` в деталях больше нет.
- GET `/tasks/by-slug/{slug}/presets` и `/editor/tasks/{id}/presets` возвращают все уровни с собственными пунктами в формате TaskDetail.presets. Внутри создания решения выбранный пресет остаётся накопительным: medium включает easy, high включает easy и medium.
- Списки задач возвращают `cover_photo`, детали — `cover_photo`, `photos` и `resources`. У фото стабильные URL `/api/media/photos/{id}`, у вложений — `/api/media/resources/{id}`, без expires_in. Байты обоих типов файлов кешируются в Redis, браузер использует ETag с проверкой доступа. Без фото возвращается `cover_photo: null`.
- Список черновиков возвращает лёгкий DraftSummary без полной формы и валидации. Детальный TaskDraft содержит всю неполную форму, фотографии и вложения. Публикация `/publish` переносит их к строгому Task одной транзакцией без копирования объектов MinIO. `revision` защищает все изменения формы и файлов.
- У Task только `published` и `archived`, скрытие отдельно задаётся `is_hidden`. Скрытое задание недоступно в публичном API, ранее созданные решения сохраняются.

Обычные API/БД-тесты создают схему через `Base.metadata.create_all` и удаляют через `drop_all`. Найдено исключение: тест удаления slug напрямую вызывает миграцию. Это расхождение с договорённостью зафиксировано в плане, тестовый код в рамках обновления документации не менялся.
