## 3. Ближайшие исправления

### P0-1. Восстановить получение конфигурации и создание решения — исправлено

**Причина:** реализация `configuration` находится в `services/composition.py`, экспорт из catalog удалён, три вызова остались прежними.

**Изменение:** в `api/routes/tasks.py` использовать уже импортированный `composition.configuration` в public_configuration и editor_configuration. В `services/solutions.py` импортировать и вызывать тот же сервис. Возвращать промежуточный экспорт catalog не требуется.

**Сохранить:** medium включает easy, high включает easy и medium. Детали страницы задачи по-прежнему показывают собственные пункты каждого уровня. Исправление вызова не должно объединить эти два формата.

**Готовность:** ty без ошибок, оба configuration-маршрута работают, создание решения возвращает 201 и правильные снимки. Выполнить существующие тесты каталога, решений, групп и полный набор с coverage не ниже 80%. Обновить раздел результатов и CONTEXT.md фактическими числами.

### P1-1. Привести тест удаления slug к согласованному подходу

**Наблюдение:** `tests/test_template_slug.py::test_remove_template_slug_migration_preserves_records_and_references` создаёт временные таблицы нативным SQL, вызывает `migration.upgrade()` и `downgrade()` через Alembic Operations. Контейнер изолирован, рабочая БД не используется, но это исключение из требования «тесты через Base.metadata.create_all/drop_all вместо миграций».

**Предлагаемое изменение:** оставить проверку схем OpenAPI, добавить/сохранить проверки CRUD шаблона без slug и сохранения ссылок в схеме, созданной через Base.metadata. Убрать исполнение миграции из обычного набора. Если потребуется отдельная проверка миграционных переходов, сначала согласовать такой отдельный процесс с пользователем.

**Готовность:** обычные DB-тесты не запускают upgrade/downgrade и не строят параллельную схему вручную. Проверка чистой функции split_legacy_items в test_group_levels.py допустима, она не применяет миграцию.

### P1-2. Проверить согласованность нового контракта с клиентом

Backend уже имеет изменения, которые несовместимы со старым клиентом:

- TaskDetail.presets — объект вместо массива, complications верхнего уровня удалён.
- У каждой группы обязателен level, смешанные ветки запрещены.
- TemplateCreate/Update больше не принимают slug.
- Библиотека возвращает массив групп developer_type.
- TaskDraft публикуется через publish и все изменения файлов используют revision.

**Работа после P0:** проверить клиентские типы и запросы по OpenAPI, переключение уровней, отображение пустых групп, повторное открытие черновика и фото карточек. Frontend в текущем аудите не анализировался, несовместимость конкретного экрана не утверждается.

**Готовность:** ручной или E2E-сценарий «форма → фото/вложения → публикация → карточка → выбор пресета → начало решения» проходит. Нельзя отправлять TaskDetail как тело записи без преобразования: запись использует items и массив presets.

### P1-3. Подготовить применение новых миграций к существующим данным

Не считать `alembic heads` проверкой рабочей БД. Перед отдельным развёртыванием выяснить её revision и подготовить резервную копию. В ревизии e62b9c43a105 выполняется преобразование групп и черновиков под блокировками таблиц. a73f8d291b06 удаляет slug шаблонов.

**Готовность:** составлен перечень затрагиваемых данных, проверены выбранные уровни старых пустых групп, сохранение ID пунктов и ссылок решений. Клиент после миграции повторно читает черновик при конфликте revision. Подробности и ограничения отката — в development.md. Автоматически применять миграции к рабочей БД в рамках документирования не нужно.

## 4. Технические ограничения и предложения, не новая функциональность

| Наблюдение | Следующий шаг, если понадобится |
| --- | --- |
| Удаление фото/ресурса/черновика удаляет метаданные, но не сам объект MinIO | Спроектировать отдельную очистку с повторной проверкой ссылок в обеих таблицах, периодом ожидания и dry-run. Сейчас команды очистки нет |
| Компенсация загрузки обрабатывает Exception, а не гарантирует очистку при остановке процесса | Не объявлять её гарантией отсутствия объектов без ссылок. Добавить восстановление через очистку при соответствующей задаче |
| Успешный commit и потеря ответа при publish оставляют клиенту 404 при повторе | При необходимости добавить ключ идемпотентности с привязкой к владельцу и результату. Сейчас API его не принимает |
| TaskDraft защищён revision, опубликованный Task не имеет такой версии | Блокировки сериализуют операции, но не предотвращают перезапись устаревшим полным PUT composition. Версионирование редактора требует отдельного решения |
| Черновик хранит только ID шаблона, пока не создаёт FK к нему | Удаление шаблона видно через live validation. Изменение его смысла до публикации не обнаруживается по версии, которой пока нет |
| Список черновиков валидирует каждую форму и отдельно читает её файлы | Если список станет большим, измерить запросы и пакетно загружать данные. Не путать с оптимизированными списками Task |
| URL в агрегатах и download-url постоянные, без чтения хранилища | Наличие объекта проверяется при скачивании после промаха Redis; метаданные и доступ проверяются на каждом запросе |
| Ошибка чтения после commit в некоторых операциях может дать ошибку ответа при уже сохранённых данных | При работе над устойчивостью редактора разобрать границы commit/формирования ответа. Публикация черновика уже формирует TaskDetail до commit |
| В новых миграциях встречается нативный SQL | a73f8d291b06.downgrade использует UPDATE-строку, e62b9c43a105 — LOCK TABLE. Для DML предпочтительнее выражения SQLAlchemy, платформенную блокировку не заменять без эквивалентной защиты |
| psycopg находится в dev, но нужен Alembic при запуске Docker | До перехода на runtime-образ без dev перенести зависимость. Текущий образ устанавливает dev |
| MinIO и Adminer в Compose без фиксированных версий образов | Перед воспроизводимым развёртыванием выбрать версии/дайджесты. Локальный состав сервисов сейчас работает как dev-конфигурация |

09.11.2026 по отдельному запросу реализована GitHub OAuth-аутентификация, X-User-ID удалён. Администраторы определяются ADMIN_EMAILS. CORS и настройки MinIO при публичном развёртывании настраиваются отдельно.

## 5. Что сохранять при следующих изменениях

- Не возвращать Task.draft, schema_version, TaskComplication.slug, category.type/group, help_text и таблицу связи пресетов с требованиями.
- Не вводить семантические зависимости требований или привязку к стеку без нового запроса.
- Не делать поля Task необязательными ради сохранения формы.
- Не требовать description/GitHub при старте или завершении решения.
- Не вычислять завершение решения по всем пунктам чек-листа.
- Не менять snapshots после изменения источников.
- Не пересоздавать ID существующих пунктов при сохранении дерева.
- Не объединять PostgreSQL и MinIO в вымышленную общую транзакцию.
- Комментарии и summary на русском, ожидаемые ошибки именованными классами, общие схемы отдельно, explicit PATCH.
